# 09: 管理画面から記録行を操作する

Status: ready-for-agent

**Parent:** 個人向けヘルスケアアプリ初版 — 体重記録と振り返り（healthcare-mvp）

**What to build:** 認証なしで開く表形式の DB 管理画面から体重記録を閲覧・追加・編集・削除し、計算用身長の誤登録も対象を選んで訂正できるようにする。

**Blocked by:** 05: 換算式を編集・保存し、過去分へ適用する

**対応する完成条件:** AC-04、AC-05（計算用身長の訂正）、AC-09（記録行）

## 完了条件

- [ ] アプリ内から認証なしで管理画面を開き、体重記録を表形式で閲覧・追加・編集・削除できる。
- [ ] 通常画面と同じ公開処理を呼び、必須・日付・一意性・数値・有効な換算式の検証を共通に適用する。同日の既存記録は編集として扱う。
- [ ] 対象記録の計算用身長を明示的に訂正でき、その記録の BMI だけを再計算する。
- [ ] 内部 ID・スキーマ情報・自動計算結果を直接編集できない。自由な SQL やテーブル・列の操作は提供しない。
- [ ] 削除は対象を確認し、キャンセル・検証失敗では元の記録を保持する。
- [ ] 変更を通常画面と、導入済みのグラフへ反映する。両画面で同じ保存結果と検証結果が得られることを確認する。

## 共通の完了条件

- [ ] 画面操作から結果表示まで、この Issue の範囲を実際に動作確認し、確認結果を残す。
- [ ] 保存を伴う処理は Controller が呼ぶ共通の公開処理を境界として、一時 SQLite DB で保存・再読み込み・失敗時の保持を検証する。内部の呼び出し回数や SQL 文字列を合否の基準にしない。
- [ ] 変更内容・各部分の役割・コードを読む入口と順番・確認方法を短く文書化する。MVC と専用の保存処理の責任分担を守り、必要な機能だけを増やす。
