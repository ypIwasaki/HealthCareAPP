# 05: 換算式を編集・保存し、過去分へ適用する

Status: ready-for-agent

**Parent:** 個人向けヘルスケアアプリ初版 — 体重記録と振り返り（healthcare-mvp）

**What to build:** 設定画面で体脂肪量・骨格筋量の2つの換算式を編集・保存し、過去を含む全記録を最新の有効な式で再計算する。

**Blocked by:** 04: 既存記録を編集・削除する

**対応する完成条件:** AC-06、AC-07

## 完了条件

- [ ] 2式そのものを編集でき、許可する要素を体重・対象の率・数値・四則演算・括弧・符号に限定する。任意プログラム実行を使わず、式の長さと複雑さを制限する。
- [ ] 保存前に構文と既存記録すべての結果を検証する。許可外の式・ゼロ除算・非有限値・負の換算重量・体重を超える換算重量を拒否し、原因を表示する。
- [ ] 一部の既存記録だけで失敗する式も切り替えない。検証失敗・DB 保存失敗では旧式と全記録を保持する。
- [ ] 式の保存を整合した単位で行い、再起動後も新しい式を使う。元の体重と率を変更せず、全記録の換算値と一覧を更新する。
- [ ] 新規登録・編集も有効な式で検証し、その入力で計算できなければ保存しない。
- [ ] グラフ導入後も同じ有効な式による取得・更新の仕組みを利用する。BMI の固定式と記録の計算用身長は変更対象にしない。

## 共通の完了条件

- [ ] 画面操作から結果表示まで、この Issue の範囲を実際に動作確認し、確認結果を残す。
- [ ] 保存を伴う処理は Controller が呼ぶ共通の公開処理を境界として、一時 SQLite DB で保存・再読み込み・失敗時の保持を検証する。内部の呼び出し回数や SQL 文字列を合否の基準にしない。
- [ ] 変更内容・各部分の役割・コードを読む入口と順番・確認方法を短く文書化する。MVC と専用の保存処理の責任分担を守り、必要な機能だけを増やす。
