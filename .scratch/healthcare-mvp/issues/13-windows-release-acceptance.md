# 13: Windows 配布物で初版の完成条件を確認する

Status: ready-for-agent

**Parent:** 個人向けヘルスケアアプリ初版 — 体重記録と振り返り（healthcare-mvp）

**What to build:** 全機能を含む Windows 配布物で、初版の完成条件と機能間の連携を確認し、利用・ビルド手順を揃える。

**Blocked by:** 07: グラフの表示期間を選択する、08: 同じ単位の指標をグラフで比較する、10: 管理画面から設定を確認・編集する、12: バックアップから全体を安全に復元する

**対応する完成条件:** AC-01〜AC-12

## 完了条件

- [ ] 全機能を含む Windows 実行ファイルを作り、アイコンから起動できる。日常利用に WSL・端末・別途インストールした Python を必要としない。
- [ ] 親仕様の Testing Decisions に対応する自動チェックが通り、AC-01〜AC-12 の確認結果を残す。
- [ ] 実行ファイルで初期設定・入力と保存・同日編集・削除・再起動後の保持を確認する。
- [ ] 項目別・kg 比較・% 比較、すべての期間選択、欠測の表示を確認する。式変更で過去の換算値・一覧・グラフが更新されることを確認する。
- [ ] 管理画面からの操作が通常画面とグラフに反映され、同じ検証が働くことを確認する。
- [ ] バックアップ後に記録・身長設定・式を変更して復元し、取得時点の状態に戻ることを実行ファイルで確認する。
- [ ] 利用・ビルド・確認の手順を残し、実際の健康データとバックアップを配布物・リポジトリに含めない。食事記録など親仕様の対象外を追加しない。

## 共通の完了条件

- [ ] 画面操作から結果表示まで、この Issue の範囲を実際に動作確認し、確認結果を残す。
- [ ] 保存を伴う処理は Controller が呼ぶ共通の公開処理を境界として、一時 SQLite DB で保存・再読み込み・失敗時の保持を検証する。内部の呼び出し回数や SQL 文字列を合否の基準にしない。
- [ ] 変更内容・各部分の役割・コードを読む入口と順番・確認方法を短く文書化する。MVC と専用の保存処理の責任分担を守り、必要な機能だけを増やす。
