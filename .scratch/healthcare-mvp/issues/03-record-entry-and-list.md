# 03: 体重記録を保存し、自動計算付きの一覧で確認する

Status: ready-for-agent

**Parent:** 個人向けヘルスケアアプリ初版 — 体重記録と振り返り（healthcare-mvp）

**What to build:** 測定日と必須の計測値を入力して体重記録を保存し、BMI・体脂肪量・骨格筋量を含む一覧で振り返れるようにする。

**Blocked by:** 02: 初期設定で身長を登録・変更する

**対応する完成条件:** AC-02、AC-04、AC-05（新規保存・初期計算）

## 完了条件

- [ ] 測定日は Windows の当日を初期表示し、当日・過去日を保存でき、未来日は拒否する。
- [ ] 体重 kg・体脂肪率 %・骨格筋率 % は小数第1位まで、基礎代謝 kcal/日は整数の必須入力とする。基礎代謝は機器表示値を保存する。
- [ ] 空欄・非数値・非有限値・不正な符号や範囲・精度超過を拒否する。体重と基礎代謝は正、率は0〜100%とし、率の両端を受け付ける。
- [ ] 測定日に DB の一意制約を設けて同日重複を防ぐ。同日の既存内容を開いて編集する操作は Issue 04 で完成させる。
- [ ] 新規記録に現在の設定から計算用身長を保持する。身長設定の変更で過去記録の計算用身長と BMI は変わらず、新規記録には新設定を使う。
- [ ] BMI は体重 kg ÷ 身長 m の2乗、初期の体脂肪量・骨格筋量は体重 × 対象の率 ÷ 100 とする。初期換算式を設定として保持し、換算値は元データと有効な式から算出する。
- [ ] 小数第1位までの元データを10倍した整数で保存し、十進数で計算する。途中で表示精度に丸めず、計算結果を小数第1位まで表示する。
- [ ] 一覧に保存値と自動計算結果を単位付きで表示し、再起動相当の再読み込みでも同じ内容を取得できる。

## 共通の完了条件

- [ ] 画面操作から結果表示まで、この Issue の範囲を実際に動作確認し、確認結果を残す。
- [ ] 保存を伴う処理は Controller が呼ぶ共通の公開処理を境界として、一時 SQLite DB で保存・再読み込み・失敗時の保持を検証する。内部の呼び出し回数や SQL 文字列を合否の基準にしない。
- [ ] 変更内容・各部分の役割・コードを読む入口と順番・確認方法を短く文書化する。MVC と専用の保存処理の責任分担を守り、必要な機能だけを増やす。
