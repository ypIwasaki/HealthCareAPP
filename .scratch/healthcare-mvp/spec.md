# 個人向けヘルスケアアプリ初版 — 体重記録と振り返り

Status: ready-for-agent

仕様合意日: 2026-09-16。利用者が承認済みの要件・設計判断・完成条件を、ローカル Issue tracker の実装用仕様に整理したもの。

## Problem Statement

利用者である開発者本人は、自分の体重・体組成を日ごとに記録し、過去の数値と変化を Windows PC で振り返りたい。毎回転記する項目はできるだけ減らし、同じ期間の複数指標を比較したい。

また、生成されたコードを自分で理解しながら Python とアーキテクチャを学びたい。一度に大きなアプリを作るのではなく、画面操作から計算・DB 保存・再表示までを追える単位で実装を進める必要がある。現在のリポジトリには設計文書とスキルがあり、アプリ本体・アプリ用テストはまだない。

## Solution

本人の Windows PC 内で使う、日本語のデスクトップアプリを作る。アイコンから起動し、1日1件の体重記録をローカル DB に保存する。BMI と kg 換算値は自動計算し、一覧・単独グラフ・同じ単位の比較グラフで振り返れるようにする。

体脂肪量と骨格筋量の換算式はアプリ内で編集・保存でき、変更時には過去分も新しい式で再計算する。認証なしの DB 管理画面と、記録・設定・式をまとめた手動バックアップ／全体復元も初版に含める。食事記録は次の版で扱う。

## User Stories

1. 利用者として、Windows のアイコンからアプリを起動したい。日常利用のたびに開発環境を立ち上げずに済むようにするため。

4. 利用者として、最初に身長を登録したい。毎日の入力で同じ値を繰り返し入力しないため。

## Implementation Decisions

### 技術構成と責任の分離

- Python、PySide6 の Qt Widgets、Matplotlib、SQLite を採用する。DB アクセスには Python の sqlite3、Windows 用実行ファイルの作成には PyInstaller を使う。
- WSL で編集と画面に依存しない処理の確認を行い、Windows 側で GUI・保存場所・実行ファイルを確認する。バージョンは実装開始時に互換性を確認して固定する。
- MVC を採用する。View は入力・結果表示、Controller は操作の調整、Model はデータ・入力ルール・計算を担当する。SQL とトランザクションは専用の保存処理にまとめる。
- 論理的な機能は、記録、プロフィールと換算設定、グラフ、DB 管理、バックアップ／復元に分ける。各段階で必要なものだけを増やす。
- 通常画面と管理画面の Controller は同じ公開処理を使う。公開処理は記録の登録・取得・更新・削除、設定の変更、換算、バックアップ・復元という利用者の操作を表す。既存コードや変更対象の既存インターフェースはない。
- 表表示に使う Qt Model/View は画面の仕組みとして扱い、アプリ全体の Model と同一視しない。

### 入力・保存する情報

| 項目 | 入力・算出方法 | 単位・精度 |
| --- | --- | --- |
| 測定日 | 必須入力、1日1件 | 日付 |
| 体重 | 必須入力 | kg、小数第1位まで |
| 体脂肪率 | 必須入力 | %、小数第1位まで |
| 骨格筋率 | 必須入力 | %、小数第1位まで |
| 基礎代謝 | 体組成計の表示値を必須入力 | kcal/日、整数 |
| BMI | 体重と記録の計算用身長から自動計算 | 表示は小数第1位まで |
| 計算用身長 | 初期設定値を各記録に保持 | cm、小数第1位まで |
| 体脂肪量・骨格筋量 | 保存された換算式から自動計算 | kg、表示は小数第1位まで |

- 測定日の初期値は Windows の当日とする。過去日は入力可能、未来日は不可。同日の記録があれば既存内容を開いて編集し、保存時に変更を確定する。
- 体重・身長・基礎代謝は正の有限値、率は0〜100%とする。必須項目の空欄、数値でない値、精度を超えた入力は修正を求め、黙って丸めない。健康状態の判定は行わない。
- 通常画面と管理画面で同じ検証を適用する。保存前のキャンセルで元データを変えず、削除前は対象を示して確認する。
- 元データとして測定日、体重、体脂肪率、骨格筋率、基礎代謝、計算用身長を保持する。設定として新規記録用の身長と有効な2式を保持する。
- 測定日には DB の一意制約も設ける。小数第1位までの元データは10倍した整数で保存し、計算は十進数として扱う。計算途中は表示精度へ丸めず、表示時に丸める。
- DB 形式の版を管理する。保存場所は Windows ユーザーのアプリデータ領域とし、実行ファイル・ソースコードから分離する。

### 計算と履歴

- 初期の項目定義はオムロンの定義を採用する。使用機種は特定せず、実機の定義との一致を確認済みとは扱わない。
- BMI は体重 kg を身長 m の2乗で割る標準式に固定する。初期設定で身長を登録し、各記録には計算時の身長を保持する。
- 身長設定を変えても過去の計算用身長と BMI を自動で変更しない。過去記録を通常編集するときも計算用身長は保つ。誤登録の訂正は管理画面で対象記録の計算用身長を明示的に編集する。
- 基礎代謝は機器表示値を保存する。独自の推定式には置き換えず、推定のためだけの年齢・性別登録は追加しない。
- 初期の体脂肪量は体重と体脂肪率の積を100で割り、骨格筋量は体重と骨格筋率の積を100で割って求める。
- 2つの換算式そのものを編集・DB 保存できる。許可する要素は体重、対象の率、数値、四則演算、括弧、符号とする。任意のプログラムを実行する方式は用いない。
- 換算式の変更は過去を含むすべての記録へ適用する。元の体重と率を正本として残し、換算値は現在の有効な式から求める。式を切り替えたら一覧・グラフも再取得して更新する。
- 保存前に式の構文と、既存記録すべてでの結果を検証する。ゼロ除算、非有限値、負の換算重量、体重を超える換算重量は保存を拒否し、問題を示して元の式・データを保つ。新規記録と記録の編集でも同じ計算チェックを行う。
- 式の切り替えと DB の保存を整合した単位で扱う。構文解析には長さ・複雑さの制限を設ける。

### 一覧・グラフと期間

- 日本語の UI とし、項目ごとの折れ線グラフを選択できる。初期期間は直近28日とする。
- 直近7・14・21・28日は Windows の当日を含む日数とする。全期間と、開始日・終了日の両端を含む任意期間にも対応する。開始日が終了日より後なら修正を求める。
- 未記録日は空白として線を途切れさせる。ゼロ埋めや補間は行わない。
- kg 比較では体重・体脂肪量・骨格筋量から表示対象を選んで同じ縦軸に重ねる。% 比較では体脂肪率・骨格筋率を重ねる。BMI と基礎代謝は各単独グラフで表示する。
- 元の率と換算重量は、項目名と単位で区別する。

### DB 管理とバックアップ

- 管理画面には認証を設けない。記録・身長設定・換算設定を表形式で確認できる。
- 記録は行単位で追加・修正・削除できる。設定は既定の行を編集する。内部 ID、スキーマ情報、自動計算結果は直接編集しない。
- 管理画面でも通常の保存・検証処理を呼び、変更後は関連画面を更新する。
- 手動バックアップは SQLite のバックアップ機能を使い、ファイル選択画面で保存先を指定する。既存ファイルへの保存は確認する。
- バックアップには記録、各記録の計算用身長、現在の身長設定、有効な換算式を含める。復元はこれらすべてを取得時点へ戻し、現在の記録とはマージしない。
- 復元元はファイル選択画面で指定し、一時領域で対応形式・記録・設定・計算可能性を検証する。実行確認後に現在の DB を退避して切り替える。退避や復元が失敗したら現在の DB を保持する。
- 復元後の換算値は復元された式と記録から求める。実際の健康データとバックアップはリポジトリへ含めない。

## Testing Decisions

### テストの主な境界

設計相談で承認された、通常画面・管理画面の Controller が呼ぶ共通の公開処理を主要な境界とする。内部の関数ごとにテストの入口を増やさず、利用者の操作に相当する入力と、取得できる結果・保存状態・エラー・復元結果を検証する。

テスト用の実際の一時 SQLite DB とバックアップファイルを使い、保存から再読み込みまで含めて確認する。画面部品の大きさ、内部メソッドの呼び出し回数、SQL の文字列など、実装に依存する詳細は合否の基準にしない。

この境界で、記録、プロフィールと換算設定、グラフ向けの取得・計算、DB 管理から共通利用する処理、バックアップ／復元を検証する。Windows の配布物に関する動作は、同じ外部振る舞いを画面から少数の代表操作で確認する。

### 代表シナリオ

| 対象 | 検証する外部の振る舞い | 対応する完成条件 |
| --- | --- | --- |
| 初期設定・保存 | 身長を登録して記録を保存し、接続やアプリを開き直して同じ記録と設定を取得できる | AC-02 |
| 日付・一意性 | 当日と過去日は保存でき、未来日は拒否する。同日の保存は既存編集となり、件数が増えない | AC-03、AC-04 |
| 入力チェック | 必須不足、非数値、非有限値、負数、率の範囲外、入力精度超過を拒否し、既存値を保持する。0%・100%は定義した境界として扱う | AC-04 |
| 訂正・削除 | 記録を修正・削除した結果を再取得できる。キャンセルと失敗では変更前の状態が残る | AC-03 |
| 自動計算 | 既知の体重・率・身長に対して期待する BMI と換算値が得られ、表示精度が合う。途中での丸めで結果が変わらない | AC-05 |
| 身長の履歴 | 設定の身長だけ変えても過去 BMI は変わらず、新しい記録には新しい身長を使う。対象記録の計算用身長を明示訂正した場合はその記録を再計算する | AC-05 |
| 式の保存と過去分反映 | 異なる日の複数記録を作り、式を変更してすべての換算値が変わる。元の体重・率は変わらず、再起動相当の再読み込み後も新しい式を使う | AC-06 |
| 式の異常 | 許可外の式、ゼロ除算、範囲外の結果を拒否する。既存記録の一部だけで失敗する式も切り替えず、古い式と全記録を保持する | AC-07 |
| 式と新規入力 | 既存記録で有効な式でも、追加・編集する値で計算できなければ保存を拒否する | AC-07 |
| 期間・欠測 | 当日を固定し、7・14・21・28日の両端、全期間、任意期間、期間外、未記録日の空白を確認する。グラフ上でも線が途切れ、比較系列の単位が合う | AC-08 |
| 管理画面 | 同じ操作を通常画面と管理画面から行って同じルールが適用され、一覧・グラフにも反映される | AC-04、AC-09 |
| バックアップ往復 | バックアップ後に記録・身長設定・換算式を変更し、復元で元の状態と換算結果へ戻る。新たに追加した記録も残らない | AC-10 |
| 復元失敗 | 不正形式・非対応形式・無効な内容を拒否する。退避／切り替えに失敗する条件でも既存の利用可能な DB が保たれる | AC-11 |
| Windows 配布物 | アイコン起動、入力と保存、再起動、グラフ、式変更、管理画面、バックアップ／復元を実際の Windows 実行ファイルで確認する | AC-01〜AC-12 |

### 既存のテスト資産と進め方

アプリ本体・既存のテスト・テスト実行設定はまだない。新しい業務機能ごとの境界を多数作るのではなく、承認済みの共通処理の境界を最初の記録機能で用意し、後続の機能も同じ位置で検証する。各段階に必要なチェックを追加し、Windows の最小起動確認は段階0で行う。

## Out of Scope

今回の初版では以下を作らない。

- 食事記録、食品データベース、栄養・カロリー集計。食事機能は次の版で設計する。
- スマートフォン版、ブラウザ版、macOS／Linux 向けの配布。
- 複数利用者、アカウント登録、ログイン、管理画面の認証。
- クラウド保存、複数 PC 間の同期、ネットワーク DB サーバー。
- 同じ測定日の複数件記録、測定時刻単位の履歴、朝と夜の比較。
- 基礎代謝のアプリ独自推定、BMI の計算式編集、基礎代謝推定のための年齢・性別登録。
- 任意のプログラムを実行する計算式、初版で定めた2式以外の換算式の追加。
- SQL 自由入力、テーブル・列の作成や削除、スキーマ情報・内部 ID・自動計算結果の直接編集。
- 自動バックアップ、クラウドバックアップ、復元時の記録のマージ。
- 体組成計との自動連携や CSV 一括取込。初版は合意した必須項目を手入力する。
- 健康状態の判定や、目標・助言など記録と振り返りを超える機能。

## Further Notes

### 段階的な実装順序

| 段階 | 実装単位 | 確認すること |
| --- | --- | --- |
| 0 | 最小画面と Windows 起動・ビルド | 実行ファイルをアイコンから開ける |
| 1 | 身長設定、記録の入力・保存・一覧、初期式の計算 | 一連の操作と再起動後の保存内容を追える |
| 2 | 編集・削除・入力チェック | 同日編集・過去日・未来日拒否・キャンセルが動く |
| 3 | 換算式の編集・保存・過去分再計算 | 全期間への反映と再起動後の保持を確認する |
| 4 | 単独・比較グラフと期間選択 | 範囲・欠測・単位が正しい |
| 5 | DB 管理画面 | 共通の処理を表形式の画面から使える |
| 6 | 手動バックアップ・復元、最終配布確認 | 記録と設定をまとめて復元し、初版の全完成条件を満たす |

各段階は小さなレビュー可能な変更として進め、必要なモジュールだけを増やす。変更した機能、ファイルの役割、コードを読む入口と順番、動作確認方法を短く説明する。
