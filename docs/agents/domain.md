# Domain docs

このリポジトリは single-context 構成とする。

- 用語集: ルートの `CONTEXT.md`
- 設計判断: `docs/adr/`

## 調査前に読む文書

コードベースの調査前に `CONTEXT.md` と、作業対象に関係する `docs/adr/` 内の ADR を読む。

文書がまだ存在しなければ、そのまま作業を続ける。不在の報告や先行作成の提案は不要。用語や設計判断が確定した時点で `/domain-modeling` を使って作成・更新する。`/grill-with-docs` や `/improve-codebase-architecture` からもこのスキルを利用する。

## 用語集の語彙を使う

Issue のタイトル、提案、仮説、テスト名を含め、ドメイン概念には `CONTEXT.md` で定義された用語を使う。用語集が避けると定めた同義語は使用しない。

必要な概念が未定義なら、独自の言い換えをしていないか確認する。実際に定義が不足している場合は `/domain-modeling` で扱う課題として記録する。

## ADR との矛盾を示す

既存 ADR と矛盾する提案をする場合は、対象の ADR 番号と再検討が必要な理由を明示する。
