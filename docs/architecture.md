# 初版の構成と読む順番

状態: 確定。2026-09-16 に利用者が承認した。機能要件と完成条件は `.scratch/healthcare-mvp/spec.md` を参照する。

## MVC の役割

| 役割 | 責任 | このアプリでの例 |
| --- | --- | --- |
| View | 入力を受け取り、結果やエラーを表示する | 体重記録フォーム、履歴表、グラフ、設定画面 |
| Controller | 画面操作を受け、必要な処理を呼び、表示更新を調整する | 保存ボタンから記録の保存処理を呼び、一覧を更新する |
| Model | データ、入力ルール、計算と操作の意味を表す | 測定日ごとの記録、BMI、換算式の評価、記録の保存・取得 |
| 保存処理 | DB やバックアップの実際の読み書きをまとめる | SQLite 接続、SQL、トランザクション、DB バックアップ |

Model は DB のテーブルだけを指さない。日付・数値・計算のルールを Python で表現し、画面を起動せずに確認できるようにする。表の表示で使う Qt Model/View は View 側の部品として扱う。

## 一つの操作を追う

```text
画面の保存ボタン
  → Controller
  → 共通の記録保存処理（入力チェック、計算用身長、換算の確認）
  → 保存処理（SQLite へ書き込み）
  → 結果を Controller に返す
  → 一覧・グラフを読み直して View に表示
```

通常画面と DB 管理画面は同じ記録保存処理を使う。管理画面から SQL を直接実行してルールを飛び越える経路を作らない。

## 機能ごとの分割

- 記録: 入力、一覧、編集、削除。
- 設定: 現在の身長、体脂肪量と骨格筋量の換算式。
- グラフ: 期間選択、単独表示、同じ単位の比較表示。
- DB 管理: 記録・設定を表から操作する入口。
- バックアップ: 保存、検証、復元。

各機能の画面と Controller を近くに置く。計算・検証・保存は共通の処理へまとめる。最初からすべての機能を作らず、仕様書の段階に従って必要な分だけ増やす。

## 入力値と計算結果の関係

- 保存する元データ: 測定日、体重、体脂肪率、骨格筋率、基礎代謝、その記録の計算用身長。
- 保存する設定: 新規記録用の身長と、有効な2つの換算式。
- BMI: 記録の体重とその記録に保持した身長から求める。
- kg 換算値: 記録の体重・率と、現在保存されている有効な式から求める。

換算値は元データと有効な式から表示時に求め、別の正本として重複保存しない。式の変更後は表示中の一覧・グラフも再取得する。これにより過去分への反映で元の計測値を書き換える必要がなくなる。

## 換算式の扱い

初期式は、体脂肪量に `weight_kg * body_fat_percent / 100`、骨格筋量に `weight_kg * skeletal_muscle_percent / 100` を使う。画面には各変数の日本語名を表示する。

Python の構文解析を利用する場合も、許可した変数・数値・四則演算・括弧・符号だけを評価する。任意の Python コードを `eval` や `exec` で実行する方式は採用しない。式の長さや複雑さを制限し、エラーを利用者が直せる形で返す。

新しい式は保存前に既存記録すべてで計算可能かを確認し、DB 上でも整合した状態で切り替える。保存失敗時には以前の式を保つ。新規記録と記録の編集にも同じ計算チェックを適用する。

## DB と復元

- SQLite の測定日に一意制約を設け、アプリの検証と DB の両方で1日1件を守る。
- 身長や率など小数第1位までの元データは、10倍した整数として格納する。BMI と式の計算では十進数として扱い、画面に渡す直前に表示精度へ丸める。
- 起動時に DB の形式を確認し、スキーマの版を管理する。内部の管理情報は DB 管理画面の編集対象から外す。
- 保存先は Windows ユーザーのアプリデータ領域とし、配布フォルダと分ける。実際の健康データやバックアップを Git に入れない。
- バックアップは SQLite のバックアップ機能を使い、実行中の DB を単純なファイルコピーで扱わない。
- 復元は一時領域で形式・記録・設定を検証し、現在の DB を退避してから切り替える。開いている接続を管理し、失敗した場合に元の DB を使い続けられるようにする。

## 開発と確認

- 編集と画面に依存しないロジックの確認は WSL で行える。
- GUI・Windows の保存場所・実行ファイルの確認は Windows 側の Python 環境で行う。
- 最初の段階で、小さなウィンドウの Windows 起動と PyInstaller による実行ファイル作成を確認する。
- Python・PySide6・Matplotlib・PyInstaller の組み合わせは実装開始時に互換性を確かめて固定する。
- 計算、日付の一意性、式の保存と全期間への反映、DB の再読み込み、バックアップと復元を自動チェックする。画面操作は Windows の実行ファイルでも確認する。
- 各段階の説明には、変更したファイルの役割、最初に読む入口、操作を追う順番、確認方法を残す。
